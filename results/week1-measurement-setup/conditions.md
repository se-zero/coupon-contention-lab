## 알려진 한계

1. **로컬 Docker 환경이므로 절대 수치는 실제 서비스와 다르다.** 특히 WSL2 가상화 계층을 거치는 커밋 fsync 가 서버급 NVMe 보다 느리다. 의미가 있는 것은 비교군 간의 상대적 차이와 꺾이는 지점이다. (브리프 3.4)
2. **k6 를 부하 대상과 같은 호스트에서 돌린다.** 부하 생성기가 CPU 를 나눠 쓰므로 최대 처리량이 다소 낮게 나온다.
3. **Grafana 의 응답 시간 패널은 서버 처리 구간만 잰다.** Micrometer 타이머는 요청이 톰캣 워커 스레드에 배정된 뒤부터 시작하므로, 스레드 대기 큐 시간이 빠진다. **NFR-03 판정은 k6 결과로 한다.** (브리프 3.3의 측정 방법과 일치)
4. 컨테이너에 CPU·메모리 제한을 걸지 않았다. 같은 호스트에서 순차 측정하므로 비교군 간 조건은 동일하지만, 호스트에서 다른 작업이 돌면 영향을 받는다. **측정 중에는 다른 작업을 하지 않는다.**
