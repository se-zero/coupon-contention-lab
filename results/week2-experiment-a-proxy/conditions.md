## 무엇이 유효하고 무엇이 아닌가

- **ramp · soak** — 연결 거부 0건. 5개 전략이 같은 경로를 지났으므로 **전략 간 상대 비교로는 유효**하다. 다만 요청마다 프록시 홉이 하나 더 있어 절대 수치(처리량·P99)는 직결보다 나쁘다 (원인 확인 실험에서 W0 처리량 228 vs 302 RPS).
- **spike · chaos** — 아래 표의 "앱 미도달" 만큼 요청이 연결 단계에서 거부됐다. 거부된 반복은 0ms 에 끝나 P99 를 끌어내리고, 반복 예산(150,000)을 태워 W1 3회차는 매진에 실패했다. **P99 와 매진 여부는 쓸 수 없다.** DB 정합성(`integrity/`)과 chaos 의 `k6_issued − db_rows` 는 도달하지 못한 요청과 무관하므로 방향은 맞다.

## 이 측정에서 얻은 것 (정식 측정과 무관하게 성립)

- W2 는 ramp · spike · soak 전부에서 재시도 폭주로 무너진다 — spike 매진 실패(5.5만/10만), soak 30분에 5만 건·5xx 14,614.
- W4 의 반영 지연: ramp 뒤 324~357초, soak 뒤 782초. 부하 중 워커는 초당 ~1,100건만 옮긴다.
- chaos: W3 `k6−DB` = −1 ×3, W4 = +41,427 / +38,657 / +36,635. DB 는 둘 다 깨끗하다.
- 첫 실행 콜드 효과: 회차 1 이 회차 2·3 보다 5~10% 낮다 (Docker Desktop 기동 직후일수록 큼).
