# 3주차 숙제 결과 — soak 계단 하락의 원인

> **측정** 2026-09-19, **4회** (W3 soak 2·3회차, W0 soak 4회차, W1 soak 4회차, 커밋 `e654c38`, 실패 0).
> 조건은 [`conditions.md`](conditions.md) — 2주차 1단계와 **동일**하고 DB 계측만 추가했다.
> 2주차 관측은 [`week2-experiment-a/summary.md`](../week2-experiment-a/summary.md) 6장.

## 한 줄 결론

**짐작한 두 범인이 모두 무죄다. W3 는 예외가 아니었고, 체크포인트도 autovacuum도 하락 시점과 맞지 않는다.**
실제로 일어나는 일은 **DB 의 커밋 처리 능력이 초당 290 에서 190 으로 떨어지는 것**이고, 전략별 하락 폭은 **발급 1건당 커밋 수**에 그대로 비례한다.

---

## 1. W3 는 예외가 아니었다

2주차에 W3 는 1회만 돌렸고 하락이 없어서 이렇게 적어 두었다.

> **W3 는 W0 과 거의 같은 DB 작업을 하면서 하락이 없었다**(락만 Redis 에 있다). 이것이 단서일 수 있지만 **W3 는 1회뿐이다.**

3회를 채우니 그 1회가 예외였다.

| W3 soak | 하락률 | 시점 | 앞 → 뒤 (초당 발급) |
|---|---|---|---|
| 1회차 (2주차) | 없음 (+2.4%) | — | — |
| **2회차** | **−23.7%** | 24.0분 | 214 → 163 |
| **3회차** | **−25.0%** | 24.0분 | 212 → 159 |

전략별 종합 (2주차 + 이번).

| 전략 | 회수 | 하락률 평균 | 개별 |
|---|---|---|---|
| W0 | 4 | **−28.4% ± 9.3** | −14.5 / −33.7 / −31.5 / **−33.7** |
| W1 | 4 | **−26.5% ± 10.6** | −32.4 / −10.6 / −31.7 / **−31.2** |
| W3 | 3 | **−15.4% ± 15.5** | +2.4 / **−23.7** / **−25.0** |
| W2 | 3 | −79.6% ± 2.2 | −80.6 / −81.1 / −77.1 |
| W4 | 1 | −2.7% | −2.7 |

W3 의 평균이 낮고 편차가 큰 것은 1회차 하나 때문이다. **W0 도 1회차가 −14.5% 로 약했다.** 이 현상은 매번 같은 크기로 오지 않으며, 한두 번의 측정으로 "이 전략만 예외" 를 말할 수 없다는 것이 이번 숙제의 첫 소득이다.

## 2. 체크포인트와 autovacuum 은 원인이 아니다

계측을 붙인 이유가 이 대조였다. 네 실행 전부에서 시점이 맞지 않는다.

| 실행 | **하락 시점** | 체크포인트 완료 | autovacuum (`coupon_issue`) |
|---|---|---|---|
| W3 2회차 | **+24.0분** | +0.5 / +5.5 / +10.5 / +15.5 / +20.5 / +25.5분 | +0.5 / +11.5 / +14.5 / +18.5 / +23.5분 |
| W3 3회차 | **+24.0분** | +0.0 / +4.5 / +9.5 / +14.5 / +19.5 / +24.5분 | +0.5 / +12.5 / +15.5 / +19.5 / +25.5분 |
| W0 4회차 | **+19.5분** | +3.5 / +8.5 / +13.5 / +18.5 / +23.5 / +28.5분 | +0.5 / +12.5 / +16.5 / +21.5분 |
| W1 4회차 | **+15.5분** | +2.5 / +7.5 / +12.5 / +17.5 / +22.5 / +27.5분 | +0.5 / +13.5 / +17.5 / +23.5분 |

**체크포인트는 5분마다 규칙적으로 일어난다** (`checkpoint_timeout` 기본값). 하락 전에도 후에도 같은 간격이다. 규칙적으로 반복되는 사건은 **한 번만 일어나는 계단**을 만들 수 없다.

**autovacuum 은 불규칙하게 여러 번** 돌지만 하락 시점과 일관되게 겹치지 않는다. W3 2회차는 +23.5분과 +24.0분이 가까워 보이지만, 3회차는 +19.5와 +25.5 사이에 하락이 있고, W0 4회차는 autovacuum 보다 **앞서** 하락한다.

부수 지표도 전부 무죄를 가리킨다.

| 지표 | 하락 전 → 후 | 읽는 법 |
|---|---|---|
| 죽은 튜플 (`coupon_issue`) | 0 → 0 | autovacuum 이 밀리지 않았다 |
| 버퍼 캐시 히트율 | 1.00 → 1.00 | 디스크에서 읽는 일이 늘지 않았다 |
| GC 일시정지 | 0.3 → 0.1~0.3 ms/s | JVM 이 아니다 |
| PostgreSQL 백엔드 수 | 32 → 32 | 커넥션이 새지 않았다 |

## 3. 실제로 떨어지는 것은 커밋 처리 능력이다

하락을 사이에 두고 **정확히 역수 관계**가 성립한다.

| 실행 | 처리량 | 커넥션 홀딩 시간 | 초당 커밋 |
|---|---|---|---|
| W3 2회차 | 214 → 163 (**0.76배**) | 3.16 → 4.59ms (**1.45배**) | 218 → 170 |
| W3 3회차 | 212 → 159 (**0.75배**) | 3.22 → 4.77ms (**1.48배**) | 217 → 166 |
| W0 4회차 | 286 → 189 (**0.66배**) | 2.97 → 4.66ms (**1.57배**) | 290 → 196 |
| W1 4회차 | 266 → 183 (**0.69배**) | 111.5 → 163.3ms (**1.46배**) | 269 → 188 |

처리량 배율 × 홀딩 배율이 1.0 안팎이다. 동시에 일하는 커넥션 수가 고정(32)이므로 **트랜잭션 하나가 오래 걸리면 처리량은 정확히 그만큼 줄어든다.** 앱이 느려진 것이 아니라 한 건을 끝내는 데 걸리는 시간이 늘었다.

그 늘어난 시간은 **읽기가 아니다** (히트율 1.00). 남는 것은 쓰기, 정확히는 **커밋**이다.

### 결정적 증거 — 하락 폭은 "발급 1건당 커밋 수" 순서다

2주차 soak 에서 각 전략이 쿠폰 한 장을 발급할 때 DB 커밋을 몇 번 하는지 계산했다.

| 전략 | 발급 1건당 커밋 | 하락률 | 왜 그 값인가 |
|---|---|---|---|
| **W4** | **0.002** | **−2.7%** | 요청 경로에 DB 가 없다. 워커가 500건을 한 트랜잭션으로 쓴다 (D-06) |
| W0 | 1.013 ~ 1.020 | −28.4% | 발급 한 건이 트랜잭션 하나 |
| W1 | 1.021 ~ 1.028 | −26.5% | 〃 |
| W3 | 1.028 | −15.4% | 〃 |
| **W2** | **13.0 ~ 17.9** | **−79.6%** | 재시도마다 트랜잭션을 연다 |

**커밋을 자주 하는 전략일수록 정확히 그 순서로 더 크게 무너진다.** 열화는 락 전략의 성질이 아니라 **커밋 경로를 얼마나 자주 지나가는가**의 문제다.

W2 를 보면 더 분명하다. W2 의 초당 커밋은 **378** 로 W0 의 379 와 같은데, 발급은 1/15 다. 즉 다섯 전략이 **같은 커밋 천장**(초당 290~390)을 나눠 쓰고 있고, 그 천장이 부하 중간에 190 안팎으로 내려앉는다.

> 2주차에는 W1 의 열화를 "락 대기 중 커넥션을 점유하는 비용" 으로 읽으려다 W0 이 같은 폭으로 떨어져 그 해석을 버렸다. 그 자리에 들어갈 설명이 이것이다.

## 4. 남은 미지 — 왜 커밋이 느려지는가

여기까지가 이 계측으로 말할 수 있는 전부다. 읽기도, GC 도, 정리 작업도, 커넥션도 아니다. 남는 것은 **WAL 을 디스크에 실제로 기록하는 시간**이고, 이 환경에서 그것은 Docker Desktop 의 WSL2 가상 디스크다.

확정하려면 필요한 것.

- PostgreSQL 쪽 — WAL 기록 시간 (PG 14+ 의 `pg_stat_wal`, exporter 기본 컬렉터에는 없다)
- 호스트 쪽 — 디스크 쓰기 지연. 컨테이너 안에서는 보이지 않는다

**이것은 전략의 성질이 아니라 측정 환경의 성질이다.** 브리프 3.4 가 "로컬 Docker 환경이므로 절대 수치는 실제 서비스와 다르다" 고 적어 둔 항목의 구체적인 사례이며, 4주차 리포트에는 한계로 싣는다. 비교군 전부가 같은 천장을 나눠 쓰므로 **상대 비교는 그대로 유효하다.**

## 6. 이번 숙제가 바꾼 것

| 2주차에 적었던 것 | 지금 |
|---|---|
| "W3 는 하락이 없었다 — 단서일 수 있다" | **틀림.** 3회를 채우니 2회가 −24%. 1회차가 예외였다 |
| "체크포인트·autovacuum 같은 것을 함께 계측해야 갈린다" | **계측했고 둘 다 아니다.** 규칙적이거나 시점이 안 맞는다 |
| "하락 시점에 커넥션 홀딩 시간이 함께 뛴다. 원인은 DB 쪽" | **맞음, 그리고 더 좁혔다** — DB 안에서도 커밋 경로 |

계측을 붙인 목적은 범인을 지목하는 것이었는데 결과는 **알리바이 확인**이었다. 후보 둘을 지우고 나니 남은 하나가 드러났고, 그것을 전략별 커밋 횟수라는 **이미 가지고 있던 숫자**가 확인해 줬다.
